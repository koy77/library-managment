Тестовое задание. Система управления библиотекой. 
Цель 
Необходимо разработать небольшое веб-приложение для управления библиотекой. 
Основная часть интерфейса должна быть реализована с использованием Laravel + Blade. Для клиентской интерактивности необходимо использовать JavaScript / jQuery. 
Ограничения 
Не требуется: 
реализовывать регистрацию и авторизацию пользователей; 
реализовывать роли и права доступа; 
писать PHPUnit-тесты; 
создавать production-ready инфраструктуру; 
использовать полноценную SPA-архитектуру; 
самостоятельно писать сложную SCSS-архитектуру. 
Основные технологии: 
PHP / Laravel; 
Blade; 
JavaScript / jQuery; 
CSS/UI-библиотека на выбор. 
Дополнительные библиотеки и инструменты можно использовать по своему усмотрению. 
Что оценивается
Основное внимание будет уделено не количеству дополнительных функций, а качеству основного решения. Будем смотреть на: 
организацию проекта; 
читаемость и поддерживаемость кода; 
структуру компонентов и классов; 
работу с базой данных; 
корректность связей между сущностями; 
корректность бизнес-логики; 
обработку граничных случаев; 
валидацию пользовательских данных; 
использование JavaScript / jQuery; 
адаптивность. 
Не требуется следовать какой-либо конкретной архитектуре или паттерну. Важно, чтобы выбранное решение было понятным, обоснованным и корректно работало. 
Результат 
Необходимо предоставить ссылку на Git-репозиторий с исходным кодом проекта. 
Проект должен запускаться локально согласно инструкции в README.md . 
Функциональность 
1. Книги 
Необходимо реализовать: 
список книг; 
создание книги; 
редактирование книги; 
удаление книги. 
Для книги необходимо предусмотреть как минимум: 
название; 
год публикации; 
ISBN; 
автора; 
количество экземпляров. 
Создание и редактирование 
При создании и редактировании книги должна выполняться валидация пользовательских данных. Необходимо предусмотреть обработку ошибок валидации и их отображение в интерфейсе. 
Конкретные правила валидации определяются кандидатом исходя из выбранной структуры данных и здравого смысла. 
Список книг
В списке книг должна присутствовать пагинация. 
Необходимо предусмотреть тестовые данные для проверки пагинации. 
При этом данные должны быть осмысленными, а не представлять собой набор одинаковых записей. 
2. Авторы 
Необходимо реализовать: 
список авторов (список книг каждого автора на той же странице с возможностью раскрыть/скрыть список); создание автора; 
редактирование автора; 
удаление автора; 
Для автора необходимо предусмотреть как минимум: 
имя; 
фамилию. 
Список авторов 
В списке авторов должна присутствовать пагинация. 
Необходимо предусмотреть тестовые данные для проверки пагинации. 
При этом данные должны быть осмысленными, а не представлять собой набор одинаковых записей. 
3. Выдача книг 
Необходимо реализовать отдельную страницу со списком выдач книг. Страница должна содержать: 
модальное окно для выдачи книги; 
форму фильтрации; 
список выдач с пагинацией. 
Каждая выдача должна содержать как минимум: 
книгу; 
имя читателя; 
дату выдачи; 
дату, к которой книгу необходимо вернуть; 
статус выдачи. 
Выдача книги
На странице должна присутствовать кнопка «Выдать книгу», при нажатии на которую должно открываться модальное окно с формой. 
Форма должна позволять указать необходимые данные для выдачи, например: 
книгу; 
имя читателя; 
дату возврата. 
У книги имеется ограниченное количество экземпляров. Например, если в библиотеке есть 3 экземпляра книги и все 3 уже выданы, новую выдачу этой книги создать нельзя. 
Ошибки валидации также должны корректно отображаться пользователю. 
Возврат книги 
Возврат книги осуществляется путём удаления записи о выдаче книги из списка на той же странице. Удаление записи о выдаче из списка должно требовать подтверждения пользователя. При возврате книги количество доступных экземпляров должно изменяться соответствующим образом. 
Форма фильтрации 
Форма фильтрации должна позволять искать выдачи как минимум по: 
имени читателя; 
названию книги; 
дате выдачи; 
статусу выдачи. 
Дополнительные параметры фильтрации могут быть добавлены по усмотрению кандидата. Фильтрация должна корректно работать совместно с пагинацией. 
4. Интерфейс
Требования к дизайну минимальны. 
Можно использовать любую готовую CSS/UI-библиотеку, например Bootstrap, Tailwind или другую. Не требуется самостоятельно разрабатывать UI-компоненты или писать сложную SCSS-архитектуру. Приоритет: 
понятный интерфейс; 
корректная HTML-разметка; 
адаптивность; 
удобная работа с формами; 
понятное отображение ошибок; 
понятное отображение успешных операций; 
корректная работа модального окна. 
5. README
В репозитории обязательно должен присутствовать README.md . В README необходимо описать: 
требования к окружению; 
настройку .env ; 
запуск миграций; 
загрузку тестовых данных; 
адрес, по которому доступно приложение; 
дополнительные команды, необходимые для запуска или работы проекта.
